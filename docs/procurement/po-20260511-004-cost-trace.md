## Shared read and resolution path

`readPurchaseCostSources` and `resolvePurchaseCostSource` are used by both
posting and current status. Existing persisted source fingerprints retain the
same selected evidence fields. `readPurchaseCostStatus` checks the current
source, latest application, current descendant set, component balances and
reporting evidence before calling a component posted.

The PO summary card and cost trace, receipt processing, shipment costing and
both purchasing health panels consume that status. Receipt attempts remain immutable history. A later
supplier application can complete their current costs; a freight approval
cannot. A provisional flag cannot override complete current component proof,
and untraced flags are never silently treated as complete.

The PO summary shows outstanding supplier reviews alongside posted freight,
with a direct **Review supplier costs** action. Health links open shipment **Cost review**. Supplier issues open the exact
invoice-line cost editor and preserve the return path. Saved mismatch labels
no longer hide that editor. Read-only users can inspect it; the existing
purchasing approval permission, exact-total validation, stale-version check,
idempotent command, transaction and audit continue to control writes.

Explicit receipt retries invoke the current cost owner even after an earlier
successful attempt. Automatic recovery retains its terminal-state rules. The
owner prevents duplicate applications for an unchanged source and lot graph.
All cost read surfaces are invalidated after supplier reviews and receipt or
shipment updates, including an uncertain response after commit.
