The release manifest records the exact reviewed commits and deployment order. The older investigation documents describe the baseline and must not be read as the current implementation status.

## What is likely happening

No production defect frequency, inventory valuation impact or forecast accuracy is inferred from the local tests. The original fragmented navigation and component authority gaps were reproduced through code and synthetic owner fixtures; the candidate supplies the connected paths described above. Production data can still contain missing historical links, old unit evidence, incomplete quotes and unresolved costs.

## What is not proven

- Real supplier forecasts, recent stockout distortion, inventory counts and user spreadsheet results have not been reconciled against production. Planning's existing historical queries still use current catalog conversion factors where no frozen historic factor exists.
- Currency conversion authority, signed credits, tax/discount residual classification, unknown historical origins and nonrepresentable uniform-lot cost remainders remain explicit review boundaries. The candidate does not invent accounting treatment or silently absorb differences.
- A supplier quantity-price tier catalog and automatic ranked alternate supplier selection need a separate contract and operator-supplied quote data. Preserve threshold, currency, UOM, validity and source revision, then capture the selected tier on the purchase; never increase quantity solely to obtain a discount.
- Carrier tracking needs actual provider interfaces and credentials. Production reports are operator-reported evidence, not supplier or carrier telemetry.
- Archon integration needs an agreed consumer, delivery/retry/acknowledgement contract and posting ownership. Internal reporting events are durable source records, not delivered accounting entries.
- The shared graph lock has real concurrency and rollback proof. Production throughput and contention under peak warehouse load have not been benchmarked.
- Local tests use PostgreSQL 17 and installed Chrome on Windows; GitHub's configured PostgreSQL 16/Linux jobs must also pass on the exact published heads. PR checks record the current result for each release.

## Test coverage and failure modes

The release manifest contains the final command results and exact commits. Unit tests cover deterministic math, validation, domain transitions and HTTP permissions. Disposable PostgreSQL tests execute the financial, procurement, inventory and identity owners with real transactions and constraints. Browser tests exercise the real frontend with explicitly intercepted fictional API data; they prove interaction and rendering, not production connectivity.

Invalid input fails before a command commits. Conflicting versions require refreshed review. Lost responses reuse the same command key. Unsupported source evidence creates visible review states. Source/application/audit failure rolls back the financial transaction; physical receiving has its own committed boundary and durable cost recovery. History is retained through corrections and cancellation.
