# Invoice component review

`APInvoiceDetail` exposes **Cost evidence** on every invoice line. `InvoiceLineCostReview` opens a version-bound review with the recorded extended line total, product amount, packaging treatment and amount, signed adjustments, and a required reason. Unknown evidence starts blank; zero is an explicit assertion. `purchasing:approve` authorizes saving; voided invoices and non-USD invoices are read only for this command.

`invoice-cost-review-form.ts` uses the shared exact decimal input parser. Dollar amounts support four decimal places without rounding. Product and packaging must be nonnegative; adjustments preserve signed credits. BigInt addition must reconcile exactly to the recorded invoice cents. This workflow never changes the invoice document total, unit price, quantity, or header balance.

`createInvoiceCostReviewCommands.review` validates its authenticated command scope, acquires the inventory cost graph lock before invoice locks, verifies the reviewed fingerprint, saves component evidence, delegates linked purchase cost application, and records immutable before/after audit in one transaction. The durable financial command repository replays the original result after an interrupted response. Stale versions and mismatched totals reject without economic writes. An audit or cost-owner failure rolls everything back and leaves the exact command retryable.

The response distinguishes saved source evidence from downstream application results. A signed adjustment can be preserved while the cost owner requires further disposition. Missing historical lineage, unsupported currency, incomplete invoice coverage, or unknown component treatment remains review work. Saving cost evidence does not approve the invoice or imply every linked lot has been recosted. Raw stored BIGINTs are checked before conversion; an amount outside safe integer representation is preserved and rejected for review rather than rounded.

`reconcileApprovedInvoiceVarianceForPurchaseOrderLineInTransaction` now delegates cost authority to the exact component owner. Its `quantityCoverage` field is diagnostic. `state` is `confirmed_invoice_cost`, `estimated_purchase_cost`, `review_required`, or `not_applicable_non_product`; source and application states are separate. The legacy `authoritativeUnitCostMills` field is null whenever application requires review or the exact product total is not evenly divisible by its frozen base-piece denominator. Full immutable `costSources` and `costApplications` remain in the result and audit. No average of legacy invoice unit prices establishes cost authority.

Verification covers strict money parsing, blank and zero handling, signed credits, input and response contracts, component-derived summaries, AP owner transaction boundaries, real PostgreSQL command replay/stale checks/concurrency/audit rollback, invoice metadata preservation, and desktop/mobile review flows. Browser APIs are synthetic; database tests use explicitly disposable local PostgreSQL. Carrier tracking, FX conversion, adjustment disposition, and historical lineage repair are outside this review command.
