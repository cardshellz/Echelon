## Safe minimum for the current read-only prerequisite

1. One caller-owned repeatable-read, read-only transaction captures WMS demand/custody evidence and inventory positions/current encumbrance evidence. Capture all relevant rows with deterministic ordering and explicit LIMIT+1 rejection; never mark a partial census complete.
2. Retain original `variant_qty`, `reserved_qty`, `picked_qty`, and `packed_qty` unchanged. Global sums are mixed-SKU diagnostic totals, not additive ATP or comparable base units.
3. Enumerate exact outstanding build reservations, including terminal builds that still retain holds. Retain raw owner IDs, lot IDs, source locations and quantities. Missing parent/lot identity remains visible as null evidence.
4. Enumerate active canonical resources and any inactive resource with residual open quantity or picked custody. A terminal/superseded status is not permission to hide residual ownership.
5. Classify but do not erase unknown residual reservation balances. This capture does not obtain exact legacy order reservation attribution, and a signed historical ledger sum is not substituted for present owner truth.
6. WMS order planning can be proposed only for explicitly supported, reconciled demand. Build-linked demand, physical-custody discrepancies, external/3PL custody, unknown warehouses/variants, missing lines, noninventory items and reservation ownership gaps require explicit classification. Unmapped demand must not disappear behind a filter.

The new contract is `shared/types/inventory-cutover-encumbrance.ts`; its owner entry point is `captureInventoryCutoverEncumbranceInsideTransaction` in `server/modules/inventory/infrastructure/inventory-cutover-encumbrance.repository.ts`. The caller must combine these raw facts with the WMS owner DTO before any reconstruction decision.

## Proposed final authority-commit contract — not implemented or authorized here

An eventual role-gated `commit` request needs an idempotency key, actor/reason, prepared activation ID, expected authority revision, exact reviewed configuration/selection manifest hash, fresh revalidation result hash and demand/custody reconstruction hash. Hash the actor, action, target run and semantic request; exclude retry wall-clock time. Current permission must be checked even on replay.

Within one caller-owned transaction, with an explicitly tested global admission barrier:

1. Serialize concurrent commit/abort/configuration changes and drain in-flight legacy authority users. Acquire the agreed graph/head/order/resource locks without reversing any existing writer's order. Recapture after exclusion; an advisory wait does not refresh a repeatable-read snapshot.
2. Require the original prepared run, unreleased matching freeze, unchanged authority revision, complete conservative target set and exact verified provider identity evidence. Revalidate current desired quantities, demand, custody, operational builds and source eligibility. Do not regard an old dry-run hash as current stock evidence.
3. Reconstruct durable claims/shortfalls and any required custody lineage through their owning modules on the same client. Preserve independent operational-build holds and deduplicate canonical build adoptions. Unknown ownership must block the authority switch, not become free supply.
4. Seal the exact selected model, location-policy, safety-policy, channel-policy, source-binding and mapping versions; promote every reviewed head atomically, clear the promoted draft pointers and increment each revision once. Record an immutable selection manifest. Do not discard the previous sealed definitions.
5. Transition to `activating`, switch the singleton to canonical with revision+1, enqueue full absolute desired publications and append the commit receipt/event atomically. Enter the worker-eligible `active` state with separate pending/full-verification progress, or change the worker/state machine together; do not call full publication verified prematurely.
6. Commit before provider I/O. Full publication retries/readback proceed durably. Never revert the first cutover to legacy formulas. Releasing a configuration freeze must not allow queued deliveries to use stale target identities or raise obsolete desired quantities.

Minimum likely schema additions/changes are an append-only final commit/revalidation manifest and receipt type, owner-specific claim/custody migration lineage, a tested shared configuration/admission fence, and explicit post-authority full-publication verification progress. Existing immutable version tables and outbox phases should be reused. Exact DDL requires the completed connected ownership audit; removing the authority guard or adding an uncallable activation stub is not a substitute.

## Replay and concurrency checks still required

- Same command/actor/body replay returns its original result without new claims, head increments or outbox rows; changed actor/body/key reuse conflicts. Current authorization precedes replay.
- Concurrent commit/abort, configuration insertion during preparation, repeatable-read pre-freeze writer, legacy reserve versus final commit, simultaneous receives/picks/build execution, and new order admission during reconstruction must be exercised on PostgreSQL.
- Existing `enqueuePublication` computes `max(revision)+1` before conflict lookup; a direct helper retry after an existing row would compute a different payload hash. Whole-command replay currently bypasses it, but a new commit path must preserve that ordering (`inventory-availability-activation.repository.ts:739–795`).
- Complete full-catalog coverage must reject new/removed catalog members, targets or policies omitted by the prior manifest; identity comparison only for selected rows does not prove the set is unchanged.
- Provider conservative readbacks can age while preparation publishes. Final verification requires current identities and marketplace ingestion watermarks; no provider reads were performed in this audit.
