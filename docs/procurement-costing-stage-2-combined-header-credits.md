# Combined supplier totals, header adjustments and tax/return attribution

Active implementation following deployed #1993. Baseline: `9cf76be54f121ecb611e3adf8c3f4856e09f08dd`; branch `codex/supplier-combined-header-tax-return-costs`. This is continuation of A3/A4 in the existing cleanup plan. It must use the existing transaction, cost revision, inventory application, approval/audit and recovery owners.

## Evidence and required implementation

- [ ] Combined goods: extend `invoiceCostComponentEvidenceSchema` and the existing invoice review to represent one supplier goods amount with an unknown product/packaging split. Preserve that explicit basis in source identity and displays. Do not describe a combined total as a known product-only price or invent a packaging amount. Separate packaging credits require an evidenced split.
- [ ] Header amounts: `purchase_orders` owns header discount, tax and shipping; `vendor_invoices` owns the gross bill but currently has no classified header allocation owner. `readPurchaseCostSources` selects line amounts, not unallocated header differences. Add exact classified, reviewed line allocations of the original header amounts, with visible proposed defaults and overrides, conservation and current-source checks. Use the existing tax owner for tax treatment, and the existing supplier/shipment cost owners for application. Preserve original bills and cash. Trace old PO header/typed-line allocation before changing its integration so no charge is counted twice.
- [ ] Tax credits: attribute refunds to a named original tax source and its configured treatment. Cap cumulative refunds both on that source and, when selected, its saved receipt interval. Inventory tax credits reduce the corresponding selected cost; recoverable tax credits stay outside inventory. Retain source evidence, approval, reversal and original tax amounts. Do not infer a tax type or refund treatment.
- [ ] Returns: trace the immutable quarantine/accepted-return owners and the original invoice-to-receipt relationship. Refunding returned goods must not reduce prices on retained receipts. Keep accepted-stock outgoing valuation and financial credit settlement under their existing owners. Add exact supported attribution and a direct review path for genuinely missing source evidence.
- [ ] Source propagation: invoice correction, tax review, header edit, AP transitions, receipt assignment, supplier credits/reversal, transfer/repacking and shared reads must retain these classifications and exact scopes. Do not add another posting engine.
- [ ] Acceptance: deterministic domain cases; real PostgreSQL/HTTP transactions; desktop/mobile connected flows; unchanged bills/cash/counts/prior approvals; partial receipts/provisional pieces; exact remainders; stale data; current assigned authority; concurrency; audit failure rollback; durable retry; credit void and source withdrawal.
- [ ] Publish/update the PR and plan; verify final-head hosted checks separately from merge/deployment/live approval.

Proposed by-value header allocations are review defaults, not facts about the supplier's intent. The approver must see each line's before/after and can override the proposed shares. Unsupported evidence remains visible; a named review is not proof that costs have posted.
