## What changes

For a paid line containing three packs split into parcels of two and one, a Shopify update reporting `quantity=3`, `current_quantity=3`, and `fulfillable_quantity=1` must preserve the three-pack commercial ceiling. The one-pack value is remaining channel work. The second parcel consumes the unused one pack of the original allocation source. A subsequent carrier event for the first parcel reuses its saved physical item and request, rather than counting another two packs.

## Transaction and failure behavior

The actual production authority constraint from [migration 108](../migrations/108_oms_wms_authority_constraints.sql), `wms.enforce_oms_wms_authority_item`, lines 127–237, remains enabled and unchanged. It still rejects active WMS quantity exceeding OMS authority. No migrations or new prefix are introduced.

`createPackageAllocationLabelCommercialWorkflow` in [package-allocation-label-commercial-workflow.ts](../server/services/package-allocation-label-commercial-workflow.ts), lines 61–116, retains its serializable transaction and retry behavior. Failure during activation rolls back the allocation, canonical physical package, projection, and command writes together. The independently recorded authoritative provider label remains available as evidence for retry. Post-commit commands retain the existing leases, receipts, request hashes, and exact provider readback before repeating an uncertain external operation.

Corrupt split identity, non-conserved capacity, changed replay quantity, conflicting provider package identity, wrong request/warehouse, cancellation/refund disposition, and true replacement of carrier-possessed units remain rejection/review cases. These guards must not be bypassed to recover a particular order.

## Impact

Affected paths are Shopify line authority/readiness; Shopify and eBay additional-label versus replacement admission; WMS package-source bootstrap/enrichment and read-only previews; and canonical carrier follow-up for allocation-backed physical parcels. The stored quantity unit stays the ordered SKU unit: for the incident, three five-box packs, with parcel quantities two and one.

This change adds a `SELECT` dependency on `wms.package_allocation_source_lines` to the existing package-authority preview reader. Its required-relation declaration and [audit credential documentation](PACKAGE-ALLOCATION-AUTHORITY-RESOLUTION-AUDIT.md) were updated. Deployment does not grant permissions or run the credential configuration workflow; installations using the separate audit role need to verify its existing grants through that approved workflow.

Picking/replenishment policy, ATP, stock posting, lot/cost calculations, provider pricing, carrier possession rules, channel notification defaults, and the picker/customer UI have no implementation changes in this batch. The implementation does not invent picks, inventory transactions, receipts, or zero costs to obtain admission.
